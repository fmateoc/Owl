This fork extends Owl (upstream `mdlacasse/Owl`) so that one NY-metro couple can decide when to retire, when to claim SS, whether to work part time, where to live (Yonkers / NYC / rest of Westchester / NJ, or a later move) and whether to rent or buy. Read these first, in this order:

1. `fork-notes/phase1-revised.md` — what is done, what was decided and why, measured stakes, revised priorities. Its last section ("Reassessment") is the current plan.
2. `fork-notes/phase0/phase0-scenarios.md` — how the household's scenarios are run (`owlcli run` / `owlcli compare`).
3. `PROGRESS.md` (repo root, fork-only like this file): the running log of what is done, filed and next. Update it at the end of every work session and commit it with the work.

## Conventions

- **Upstream:** CONTRIBUTING says branch from and target `dev`. The maintainer implements fixes himself from issues, crediting the reporter. He has not merged our PRs. So send each finding as an issue with a repro on stock `dev` and a minimal patch verified against stock `dev`, and large features as a design issue. Draft issues in `fork-notes/`; the user files them. New information or a concrete test case beyond what was filed is always worth filing, whatever the maintainer is testing himself (user, 2026-10-16); this overrides "don't stack comments" (`phase3-plan.md` lesson 9) for new evidence, not for repeating a question.
- **Syncing:** `git merge upstream/dev` with a merge commit. Never rebase or force-push this branch. When upstream lands one of our fixes, take theirs and drop our duplicate code and tests. Upstream itself may rewrite `dev` (2026-10-11: a merged commit replayed under a new hash): compare the new commits' trees with what was already merged, and grep for duplicated definitions after the merge (`export.py` got a second `_node_limit_hits` with no conflict marker). Never `git stash` during a merge: it takes the resolution and clears the merge state. Since 2026-10-16 the fork also carries upstream branch `ss-convex` (#193 "convex"), which is not on `dev`: merge `upstream/ss-convex` as well while it exists; if upstream rewrites it or lands it on `dev` under new hashes, compare trees and expect conflicts in the same `plan.py` regions.
- **Commits:** CONTRIBUTING tags (`[feat]`, `[fix]`, `[docs]` …, `[no ci]` for docs-only).
- **Privacy:** the fork is public. Real balances, PIAs and wages live only in `otherFiles/` (gitignored by upstream itself). `fork-notes/phase0/` holds templates with placeholders.
- **Evidence:** the user wants claims checked against primary sources, and wants each statement to say whether it was verified or recalled. Tax rules come from the state's own instructions (we read IT-201-I 2018/2021/2024/2025 and NYS-50-T-* 2026 from tax.ny.gov). Data files carry a `description`/comment saying where each number comes from. Repro output pasted into an issue must come from a real run.

## Gotchas found the hard way

- **`owlcli compare`:** `--set` applies to the variant only, so the base case file must be complete (objective and `netSpending` included); `--solver-opt` applies to both runs. `netSpending` and `bequest` are read from `[solver_options]`; under `[optimization_parameters]` they are silently ignored. Before upstream #174 (merged 2026-10-08), `--solver-opt withSSTaxability=0.85` stayed the text "0.85" and did not pin; it pins now.
- **`p.basis` under `maxBequest`** is the fixed net spending, not the objective; read the bequest with `export._compute_estate(p, p.N_n)[3] / p.gamma_n[p.N_n]` (= `final_bequest_today`). A deduction variable (`st_pt`, `st_e`) in a year whose taxable income is zero anyway takes an arbitrary value: compare objectives, not amounts claimed.
- **Plans start "today":** results move from one day to the next. NJ `maxBequest` runs that stop at the exclusion MILP's node cap (gaps 0.6-1.0%) moved by $2.2k in one day (state tax 11,047 -> 6,190). Compare variants run the same day, and read the reported gap before calling a difference.
- **HFP rates:** upstream multiplies any Debts/Fixed Assets `rate` or `commission` between 0 and 1 by 100 when reading a workbook (0.5% -> 50%). The fork converts only percent-formatted cells; on upstream, type such rates as percentages in Excel (`0.5%`).
- **Budget profile:** `xi_n` comes from the Budget sheet only when `solve()` runs (clone copies the household tables after setting the profile). Under `maxSpending` every line scales, rent included; compare rent vs buy with `maxBequest` and no `netSpending`, so each variant spends its own budget.
- **`processDebtsAndFixedAssets()`** runs before any solve too (the UI's Goals page): anything it reads must be initialized in `Plan.__init__`.
- **Cliffs belong in the MILP, not the loop:** a loop-fed tier for the NJ exclusion 2-cycled and accepted a plan that undercharged its own tax by $13.9k. A big-M on income made each MILP 4-6 s; the disaggregated form takes about 1 s. Never add the same column twice to one row (`abcapi` does not merge duplicates; HiGHS crashed with "double free").
- **NJ exclusion solve limits:** tier binaries are free only in years within `RX_WINDOW` (1.5x the top ceiling) of the previous iterate's income (`RXF_n`, an SC parameter; iteration 0 runs without the exclusion). Without `maxTime`, a HiGHS MILP carrying them stops at `RX_NODE_LIMIT` (20,000 nodes; HiGHS says "Solution limit reached"), warns with the gap, and later iterations keep its tiers (`_rx_fixed`; not inside local search); `solverGap` reports that MILP's gap. Node caps give the same plan on any machine (the old 60 s cap did not); MOSEK still uses 60 s. With `maxTime` or `mipMaxNodes`, there is no RX cap. Since upstream 2026.10.10 (public `mipMaxNodes`, node rows in the Summary) every HiGHS cap goes through `Plan._node_limit`, which falls back to upstream's `_mipNodeLimit`: a new fork cap goes there too, or the Summary's *MIP solves stopped at node limit* and *MIP node limit* rows miss it.
- **Upstream's local search and fork binaries:** `localsearch.FAMILIES` must list every binary block the search may meet. A block left out is relaxed by the LP start, and the search then returns that fractional plan (it did, for `zx`, until 2026-10-06). Upstream sends its other non-family binaries (`zssa`, `zo`) to branch-and-bound before searching.
- **Loop noise:** under the default self-consistent loop, scenario differences under about 1% can come from the loop settling on different fixed points, and can have the wrong sign (NJ vs NY at $1.5M: loop −$191/yr, local search +$430, exact LP +$1,006; PROGRESS.md). For decisions, compare variants with `breakpointMethod="local-search"` (seconds to minutes each; never worse than the loop), cross-check with the exact LP (`withMedicare="None"`, `withSSTaxability=0.85`), and treat differences smaller than the spread between the two as unresolved. The SS-taxability loop is also **biased low** where many SS years sit in the 50-85% phase-in and the plan can move income (2026-10-16, PROGRESS.md "Why the NY + mortgage loop fails"): the LP prices phase-in income at the bracket rate, not up to 1.85x; on the probe couple exact SS (`withSSTaxability="optimize"`, 3-4 iterations there) leaves $34-60k more bequest, on stock upstream too. And when every account has the same allocation at fixed rates the LP is degenerate (withdrawal timing ties to the cent), so the solver's arbitrary vertex feeds Psi and the loop can hit its cap; a 1-point allocation difference removes that. Upstream's fix (2026-10-16): `withSSTaxability="convex"` prices the phase-in exactly without binaries, the same plan as `"optimize"` in 1.5-3.3 s in NY at `c22f46d`, but **4-7 min in NJ** on the fork (its cap probe re-solves the plan per year, each solve's iterations being NJ exclusion MILPs; since 2026-10-17 the probe also warm-starts the fork's `_SC_PARAMS`, a fork edit in `_ssCapProbe`'s `warm_keys`, -25 to -37%); it leaves LTCG to the loop, which cost $10.7k on the NY + mortgage probe (PROGRESS.md "Upstream #193 fix merged"). Local search overrides a pinned SS fraction with the IRS formula. It also sets `withMedicare="optimize"` (and SS taxability, LTCG, NIIT, senior bonus, ACA): anything keyed on loop-mode Medicare (`M_n` constant, `m` pinned) does not hold under local search.
- **Degenerate tests:** in a fixed-income `maxSpending` test plan, first-year income can cap spending, and later taxes then cost nothing. Use `maxBequest` with `netSpending` instead.
- **Earnings test:** not modeled. In scenarios where one spouse works, optimize SS ages only for the one who stops (`withSSAges=["Name"]`).
- **`pkill -f <pattern>`** can kill the shell running it. Kill by PID instead.
- **`python -I` ignores `PYTHONPATH`:** in a scratch worktree it imports the main checkout's code through the `.venv`'s editable install (2026-10-17: a "patched" repro ran fork code). Run your own scripts without `-I`, and print `owlplanner.__file__` when it matters. A wait loop on `pgrep -f name.py` matches its own command line and never ends; wait on an output file instead.
- **Local search and LTCG (#197):** step (b) pins the LTCG regime binaries `zl`, which hold ordinary income on one side of T15/T20, so moves that need SS and LTCG together are blocked (john+sally: preset 20,004 vs branch-and-bound 31,778). Draft issue and patch `fork-notes/issue-ls-ltcg.*`; **applied in the fork 2026-10-17** (step (b) leaves `zl` free; `tests/plan/test_local_search_ltcg.py`). When upstream lands its own fix, take theirs and drop ours. The patch is not monotone in the fork (one stand-in -$708): the outer loop's quantities follow the plan.
- **TOML arrays must be homogeneous** for the `toml` package: write `[[100000.0, 100.0], [125000.0, 37.5]]`, not mixed ints and floats.
- **Owl units:** `setAccountBalances` takes thousands of dollars; `setPension`/`setSocialSecurity` take monthly amounts. Test plans with balances entered in dollars (1000x too large) came back "infeasible" with no other hint.
- **TOML encoding:** files must be UTF-8. A Windows-1252 em dash stops `owlcli` with a `UnicodeDecodeError`.
- **Mode options are normalized to lowercase** (`utils.normalize_mode_option`): `withMedicare="None"` becomes `"none"`. Comparing `options.get("withMedicare") == "None"` is always false.
- **LP rows in dollars times dollars:** a profile row written as D_0 g_n - D_n g_0 (both in dollars) made HiGHS call feasible plans infeasible. Keep coefficients of order 1 (divide by a reference amount), as upstream's own rows do.
- **Ties where cash has no price:** with no bequest target, money left at the end is worthless, so the LP may overpay tax in late years at no cost. Upstream's bracket-order check turns tax pricing on; the fork extends it to an NJ exclusion claimed short (`_exclusion_shortfall`). Any new "at most" bound on a tax benefit needs the same check.
- **Tests freeze the date at 2026-01-01** (`tests/conftest.py`): a script run outside pytest uses today and can give another plan; freeze the date the same way to reproduce a test.
- **Owl reverts federal law in 2032 by default:** `obbba_expiration_year = 2032` (schema default, all 18 examples) switches to pre-TCJA brackets and standard deduction; the law as enacted does not. Decision D1 (2026-10-10): statutory law is the base; the template sets `obbba_expiration_year = 2066` (the UI caps it at this year + 40), 2032 is a sensitivity run. It moves the plan before 2032 as well.
- **MCP `big_ticket_items` sign:** signed, negative = expense, as in the HFP. Upstream 2026.10.10 (#180) fixed the MCP docstrings, which had described positive expenses; cases built through the MCP before that may carry expenses as income. `phase3-plan.md` §8.
- **Essential budget lines and the NJ deduction:** the amount paid is `st_ptd_const_n + st_ptd_coef_n * g_n` (`Plan._budget_amount_terms`), not `st_ptd_share_n * g_n`, which is wrong whenever k != 1 (fixed 2026-10-10).
- **Federal itemizing (`withItemized`):** `"loop"` must stay column-free: a pinned zero column alone moved a non-converging example by $215/yr. Loop-mode choices that change the LP (branch, floor sides, SALT cap) are `_SC_PARAMS` entries and count in the residual. `solve()` zeroes `MAGI_n` before `_buildOffsetMap`, so nothing built there may read it.
- **Medical claims (Phase 3 step 5):** medical paid = budget `medical` lines (or, without one, `setMedicalExpenses`' amount: `_medical_amount_terms`, never both) + premiums (`M_n + ACA_n` and the `m` / `maca` columns), less HSA distributions for federal and NY (Pub. 502), not for NJ. Read it through `_medical_premium_terms` / `_medical_premium_values` / `_medical_premium_lo`, never by hand. A floor row `claim <= paid - F` with `claim >= 0` is a lower bound on every LP column in `paid`: write it switch-free only where paid has no LP terms (`_medical_premium_lp_n`); under `withMedicare="optimize"` (and so local search) the old rows made HiGHS call the MIP infeasible.
- **State parameters are per year:** `st_tax_ss`, `st_conv_ok`, `st_fed_sd` and the other flags are arrays, because the state can change mid-plan. `st_T_n` is state + recapture + local; `st_recap_n` and `lt_T_n` are its parts. `st_agi_n` is state income before the NJ exclusion (its tiers are set on it); `st_rx_n` is the exclusion claimed.
