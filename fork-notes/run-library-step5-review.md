## Open questions for the user

- **W1's answer is a design decision**: §6.3's marker ("shown with a marker") is the minimum for
  the editor as shipped; the per-cell overrides ("closing costs 2029: 24,000 instead of 21,700")
  are the full answer and are deliberately a later increment. Fold a marker into the Budget (and
  Debts / Fixed Assets) editors now, or document "edit the event instead" beside the table?
- **W2's policy**: when the editor's Budget table is non-empty, should the sheet win over
  `budget_file` everywhere (clearing `plan.budgetFromFile` at sync, `_load_budget_file`'s own
  rule), or should the file's lines stay read-only in the pages with the caption pointing at the
  file? The current mix is the only state where one edit means three different things.
- **The "solve and save cannot drift" wording** is true for the two radios (one case key) but the
  page still has `xtra_options`, which the solve reads and the save does not (pre-existing, not
  this step's). Worth a line in the design's section 7 or a later fix.
- **Untested behaviors a reviewer would expect**: the data_editor edit loop itself (AppTest cannot
  drive `st.data_editor`; PROGRESS says so and covers it through the storage path — acceptable),
  but `_removeMove` of a **middle** row and a Budget edit followed by a Scenario-page save against
  an event-bearing base (W1's path) are cheap to add and are exactly the two places where the new
  code does its own state bookkeeping. A moves/residency parity table (the `_moreMoveWarnings`
  messages checked against `_homes_by_year`'s refusals over a grid of chains) would pin W3/W4.
- **The design's check column for step 5** (empty). I consider these sufficient: the 23 tests as
  they stand, plus (a) the moves/residency parity table above, (b) one end-to-end "edit a Budget
  line in the pages → save to the library → reopen the run" test on an event-free case (the
  step's own headline feature, currently covered only through its parts), and (c) the decision on
  W1/W2 recorded in PROGRESS's known limits if the fixes are deferred.
