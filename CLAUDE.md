# CLAUDE.md — fork `fmateoc/Owl` (not part of upstream)

This fork extends Owl (upstream `mdlacasse/Owl`) so that one NY-metro couple can decide when to retire, when to claim SS, whether to work part time, where to live (Yonkers / NYC / rest of Westchester, or a later move within NY; NJ dropped from the investigation on 2026-10-17, see "Dropped by decision") and whether to rent or buy. Changes stay generic and data-driven so they can go upstream.

Read these first, in this order:

1. `fork-notes/phase1-revised.md` — what is done, what was decided and why, measured stakes, revised priorities. Its last section ("Reassessment") is the current plan.
2. `fork-notes/phase0/phase0-scenarios.md` — how the household's scenarios are run (`owlcli run` / `owlcli compare`).
3. `PROGRESS.md` (repo root, fork-only like this file): the running log of what is done, filed and next. Update it at the end of every work session and commit it with the work.

## Conventions

- **Upstream:** CONTRIBUTING says branch from and target `dev`. The maintainer implements fixes himself from issues, crediting the reporter. He has not merged our PRs. Draft issues in `fork-notes/`; the user files them. New information or a concrete test case beyond what was filed is always worth filing, whatever the maintainer is testing himself (user, 2026-10-16); this overrides "don't stack comments" (`phase3-plan.md` lesson 9) for new evidence, not for repeating a question.
- **PR texts for upstream** (`fork-notes/pr-*-body.md`): upstream's default branch is `main`, and GitHub's PR form preselects it, so the first item of the "Before opening (user)" checklist is "Base: `dev`", with a link that opens the form with the base set: `https://github.com/mdlacasse/Owl/compare/dev...fmateoc:Owl:<branch>`. PR #228 went to `main` because the base was only mentioned in the draft's status line (2026-10-25; the maintainer squashed it into `dev` and closed it by hand).
- **Syncing:** `git merge upstream/dev` with a merge commit. Never rebase or force-push this branch. When upstream lands one of our fixes, take theirs and drop our duplicate code and tests. Upstream itself may rewrite `dev` (2026-10-11: a merged commit replayed under a new hash): compare the new commits' trees with what was already merged, and grep for duplicated definitions after the merge (`export.py` got a second `_node_limit_hits` with no conflict marker). - **Commits:** CONTRIBUTING tags (`[feat]`, `[fix]`, `[docs]` …, `[no ci]` for docs-only).
- **Changelog:** `CHANGELOG.md` stays upstream's byte for byte (since 2026-10-25); fork entries go in `fork-notes/CHANGELOG-fork.md`. At a sync, take upstream's `CHANGELOG.md` as is.

## Gotchas found the hard way

- **`owlcli compare`:** `--set` applies to the variant only, so the base case file must be complete (objective and `netSpending` included); `--solver-opt` applies to both runs. `netSpending` and `bequest` are read from `[solver_options]`; under `[optimization_parameters]` they are silently ignored. Before upstream #174 (merged 2026-10-08), `--solver-opt withSSTaxability=0.85` stayed the text "0.85" and did not pin; it pins now.
- **`p.basis` under `maxBequest`** is the fixed net spending, not the objective; read the bequest with `export._compute_estate(p, p.N_n)[3] / p.gamma_n[p.N_n]` (= `final_bequest_today`). A deduction variable (`st_e`) in a year whose taxable income is zero anyway takes an arbitrary value: compare objectives, not amounts claimed.
- **Plans start "today":** results move from one day to the next. NJ `maxBequest` runs that stop at the exclusion MILP's node cap (gaps 0.6-1.0%) moved by $2.2k in one day (state tax 11,047 -> 6,190). Compare variants run the same day, and read the reported gap before calling a difference.
- **HFP rates:** upstream multiplies any Debts/Fixed Assets `rate` or `commission` between 0 and 1 by 100 when reading a workbook (0.5% -> 50%). The fork converts only percent-formatted cells; on upstream, type such rates as percentages in Excel (`0.5%`).
- **Budget profile:** `xi_n` comes from the Budget sheet only when `solve()` runs (clone copies the household tables after setting the profile). Under `maxSpending` every line scales, rent included; compare rent vs buy with `maxBequest` and no `netSpending`, so each variant spends its own budget.
- **`processDebtsAndFixedAssets()`** runs before any solve too (the UI's Goals page): anything it reads must be initialized in `Plan.__init__`.
- **Cliffs belong in the MILP, not the loop:** a loop-fed tier for the NJ exclusion 2-cycled and accepted a plan that undercharged its own tax by $13.9k. A big-M on income made each MILP 4-6 s; the disaggregated form takes about 1 s. Never add the same column twice to one row (`abcapi` does not merge duplicates; HiGHS crashed with "double free").
- **Node limits:** HiGHS uses upstream's `_mipNodeLimit` (`mipMaxNodes`, else `HIGHS_MAX_NODES`) since the NJ exclusion's `RX_NODE_LIMIT` and its `Plan._node_limit` wrapper were removed (2026-10-17). A new fork cap would have to feed upstream's node tally too, or the Summary's *MIP solves stopped at node limit* and *MIP node limit* rows miss it.
- **Upstream's local search and fork binaries:** `localsearch.FAMILIES` must list every binary block the search may meet. A block left out is relaxed by the LP start, and the search then returns that fractional plan (it did, for the NJ exclusion's `zx`, since removed, until 2026-10-06). Upstream sends its other non-family binaries (`zo`) to branch-and-bound before searching (`zssa` is gone since #195).
- **Loop noise:** under the default self-consistent loop, scenario differences under about 1% can come from the loop settling on different fixed points, and can have the wrong sign (NJ vs NY at $1.5M: loop −$191/yr, local search +$430, exact LP +$1,006; PROGRESS.md). For decisions, compare variants with `breakpointMethod="local-search"` (seconds to minutes each; never worse than the loop), cross-check with the exact LP (`withMedicare="None"`, `withSSTaxability=0.85`), and treat differences smaller than the spread between the two as unresolved. The SS-taxability loop is also **biased low** where many SS years sit in the 50-85% phase-in and the plan can move income (2026-10-16, PROGRESS.md "Why the NY + mortgage loop fails"): the LP prices phase-in income at the bracket rate, not up to 1.85x; on the probe couple exact SS (`withSSTaxability="optimize"`, 3-4 iterations there) leaves $34-60k more bequest, on stock upstream too. And when every account has the same allocation at fixed rates the LP is degenerate (withdrawal timing ties to the cent), so the solver's arbitrary vertex feeds Psi and the loop can hit its cap; a 1-point allocation difference removes that. Upstream's prototype fix (2026-10-16, branch `ss-convex`): `withSSTaxability="convex"` priced the phase-in exactly without binaries, the same plan as `"optimize"` in seconds with the rest on the loop; it left LTCG to the loop ($10.7k on the NY + mortgage probe). Dropped from PR #196 and removed from the fork (2026-10-17); for exact SS use `withSSTaxability="optimize"` or the local-search preset. Local search overrides a pinned SS fraction with the IRS formula. It also sets `withMedicare="optimize"` (and SS taxability, LTCG, NIIT, senior bonus, ACA): anything keyed on loop-mode Medicare (`M_n` constant, `m` pinned) does not hold under local search. **Not in ACA years** (2026-10-22, `fork-notes/plan-review-2026-10-22.md` §3.2): the exact LP leaves ACA in the loop unless `withACA="optimize"` is added, and even then it mis-prices the ACA-year trade (no Medicare, SS pinned: on chris+pat with a stand-in SLCSP it valued getting under the 400% cliff at $528/yr, the case's own model at $14, local search kept the income). `--decider ls` for local search): on the chris+pat dry run the exact LP's picks then cost \$0-2/yr (local search had said \$8-99/yr: its own noise). **Branch-and-bound gap:** with no `gap` option and `withMedicare="optimize"` (so under `breakpointMethod="branch-and-bound"`), `plan.py` loosens the gap to `MILP_GAP` = 3e-3 (\$340/yr on chris+pat), and its plans then scored below local search's; Fixed upstream (`70fb8dd`, merged 2026-10-20) by freeing `zl` in every step (b); made faster upstream in `3444729` (merged 2026-10-24): step (b) pins `zl` again, the search relaxes the "zl = 0 => income at or above the threshold" half of the link rows (`ltcg_zl15_link` / `ltcg_zl20_link`, `localsearch._RELAXED_LINKS`) in its own copy, a step (b') frees `zl` with the SS ball once per loop iteration when a round makes no move, and `_restore_links` sets stranded binaries back to 1 before the repair / polish / dual solves. The fork's link rows are upstream's (a fork change to them must keep those tags); our `tests/plan/test_local_search_ltcg.py` was dropped for upstream's `test_moves_that_cross_an_ltcg_threshold_with_ss_taxability`.
- **TOML arrays must be homogeneous** for the `toml` package: write `[[100000.0, 100.0], [125000.0, 37.5]]`, not mixed ints and floats.
- **Owl units:** `setAccountBalances` takes thousands of dollars; `setPension`/`setSocialSecurity` take monthly amounts. Test plans with balances entered in dollars (1000x too large) came back "infeasible" with no other hint.
- **TOML encoding:** files must be UTF-8. A Windows-1252 em dash stops `owlcli` with a `UnicodeDecodeError`.
- **Mode options are normalized to lowercase** (`utils.normalize_mode_option`): `withMedicare="None"` becomes `"none"`. Comparing `options.get("withMedicare") == "None"` is always false.
- **LP rows in dollars times dollars:** a profile row written as D_0 g_n - D_n g_0 (both in dollars) made HiGHS call feasible plans infeasible. Keep coefficients of order 1 (divide by a reference amount), as upstream's own rows do.
- **Ties where cash has no price:** with no bequest target, money left at the end is worthless, so the LP may overpay tax in late years at no cost. Upstream's bracket-order check turns tax pricing on; the fork extends it to state and federal itemized deductions claimed short (`_itemized_shortfall`, `_federal_itemized_shortfall`). Any new "at most" bound on a tax benefit needs the same check.
- **Tests freeze the date at 2026-01-01** (`tests/conftest.py`): a script run outside pytest uses today and can give another plan; freeze the date the same way to reproduce a test.
- **Owl reverts federal law in 2032 by default:** `obbba_expiration_year = 2032` (schema default, all 18 examples) switches to pre-TCJA brackets and standard deduction; the law as enacted does not. Decision D1 (2026-10-10): statutory law is the base; the template sets `obbba_expiration_year = 2066` (the UI caps it at this year + 40), 2032 is a sensitivity run. It moves the plan before 2032 as well.
- **MCP `big_ticket_items` sign:** signed, negative = expense, as in the HFP. Upstream 2026.10.10 (#180) fixed the MCP docstrings, which had described positive expenses; cases built through the MCP before that may carry expenses as income. `phase3-plan.md` §8.
- **Essential budget lines:** a line's amount paid is `const_n + coef_n * g_n` (`Plan._budget_amount_terms`), not its share of spending times `g_n`, which is wrong whenever k != 1 (found 2026-10-10 on the since-removed NJ deduction).
- **Federal itemizing (`withItemized`):** `"loop"` must stay column-free: a pinned zero column alone moved a non-converging example by $215/yr. Loop-mode choices that change the LP (branch, floor sides, SALT cap) are `_SC_PARAMS` entries and count in the residual. `solve()` zeroes `MAGI_n` before `_buildOffsetMap`, so nothing built there may read it.
- **Medical claims (Phase 3 step 5):** medical paid = budget `medical` lines (or, without one, `setMedicalExpenses`' amount: `_medical_amount_terms`, never both) + premiums (`M_n + ACA_n` and the `m` / `maca` columns), less HSA distributions (Pub. 502; federal and NY). Read it through `_medical_premium_terms` / `_medical_premium_values` / `_medical_premium_lo`, never by hand. A floor row `claim <= paid - F` with `claim >= 0` is a lower bound on every LP column in `paid`: write it switch-free only where paid has no LP terms (`_medical_premium_lp_n`); under `withMedicare="optimize"` (and so local search) the old rows made HiGHS call the MIP infeasible.
- **STAR (fork):** the credit applies only in years with a budget `property tax` line (the owner signal) and a `school_district`. STAR income = `MAGI_n` less tax-deferred withdrawals and conversions (the tax-deferred account is taken to be an IRA; 401(k) distributions would count). `previousSTARIncomes` and `previousMAGIs` are in `units` ($k by default), like every monetary list option. `st_T_n` can be negative in a NY year (refundable credit).
- **State parameters are per year:** `st_tax_ss_n`, `st_conv_n`, `st_fed_sd_n` and the other flags are arrays, because the state can change mid-plan. `st_T_n` is state + recapture + local; `st_recap_n` and `lt_T_n` are its parts. `st_agi_n` is state AGI (`_state_agi_and_ti`).
